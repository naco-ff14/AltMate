AltMate プラグイン内Web同期（プラグイン発行コード方式）

設定場所
  /altmate → 設定 → Webダッシュボード同期

すでにPC同期アプリを使っている場合
  1. 2-start-sync.cmd で開いていた同期ウィンドウを閉じてください。
  2. プラグインの設定で「Web同期を有効にする（このクライアント）」をONにします。
  既存のPC連携・暗号化された送信待ちデータはそのまま使います。
  同じWindowsユーザーであれば、コードを発行し直す必要はありません。
  この設定はそのDalamudインストールのローカル設定として保存します。
  他のクライアントの同意を自動でONにはしません。

初めて連携する場合
  1. 同期をOFFにした状態で「Webと連携する（コード発行）」を押します。
  2. 表示された12文字のコードをコピーし「Webでログイン・連携」を押します。
  3. Webにメールアドレス・パスワード・連携コードを入力し「ログインして連携」を押します。
     ログイン済みなら「設定 → プラグイン連携」にコードを入力して承認します。
  4. プラグインが承認を確認すると同期を自動でONにします。
  パスワードはWebだけに入力し、プラグインやPC同期アプリには入力しません。
  コードは10分間有効で1回だけ承認できます。自分が発行したコードだけを登録してください。
  自動同期の設定は連携を開始したDalamudインストールにだけ保存します。
  途中でプラグインを終了した場合は「Webと連携する」を押すと有効な申請を再開します。
  自分のSupabaseを使う場合は、コード発行前に「接続先の詳細設定」でURLを変更し、自分のWebを手動で開きます。

サーバー更新（既存利用者向け・一度だけ）
  dashboard-v2.sql 適用済みの環境で plugin-pairing.sql をSQL Editorから実行します。
  Edge Functionsの sync を更新用 sync-function.ts の全文に置き換えてデプロイします。
  Verify JWT with legacy secret はOFFのままです。初期SQLは再実行しません。
  既存の連携は削除も登録し直しも不要です。

同期中の操作
  「今すぐ同期」、最終送信時刻、次の確認時刻、送信待ち状態を表示します。
  サーバーの5分間隔の制限は、手動同期でも守ります。
  制限に当たった場合はサーバー障害と区別して表示します。
  ゲームを操作するメインスレッドでは、ファイル読み出しや通信を行いません。
  同期OFFとプラグイン終了は、通信を中止し、送信待ちデータを残します。
  終了時にネットワークの完了待ちでゲームを止めません。
  実行中の通信中止時は、サーバーにすでに届いている場合もあります。
  その場合も同じ送信番号で再試行して二重取り込みを防ぎます。

複数クライアント
  同じPCでは1つのクライアントのみが送信を担当します。
  ほかの有効なクライアントは待機し、担当が終了したら引き継ぎます。
  外部Sync Agentが起動している場合も競合せず待機します。

連携を解除する場合
  同期をOFF →「PC側の連携情報を削除…」で確認して削除します。
  PC上の認証情報と送信待ちデータだけを削除します。
  Webの登録は残るので、「設定 → プラグイン連携」で「このPCの連携を解除」を押してください。

導入
  DalamudのインストーラーでAltMateを更新してください。
  /altmate → 設定 → Webダッシュボード同期 から設定できます。
  既存の設定やPC連携ファイルを削除する必要はありません。

検証範囲
  プラグインのReleaseビルド、既存の回帰テスト、同期エンジンとプラグイン用ワーカーの
  自動テストを実行しています。送信OFF・排他・再試行・中止・暗号化・同意の非伝播を確認します。
  開発版を実際にゲームへ読み込んだ際の画面・プラグインからの実送信は未検証です。
  同期元の観測内容は、既存のAltMateが保存した記録に依存します。
